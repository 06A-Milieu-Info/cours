# Analyser la profession

Dans le programme, on vous demande aussi d'analyser la profession elle-même, pas seulement les entreprises.

## Développeur d'application : un point de départ utile

Le poste de **développeur d'application** est un bon point de repère pour comprendre plusieurs réalités du domaine.

On y retrouve souvent :

- l'analyse des besoins
- la programmation
- les tests
- la correction de problèmes
- la maintenance et l'amélioration d'une application

## Tâches et responsabilités

Quand vous analysez une profession, cherchez les tâches concrètes associées au poste.

Exemples :

- développer une fonctionnalité
- corriger un bogue
- tester une application
- collaborer avec l'équipe
- documenter le travail effectué

## Connaissances, comportements, attitudes et habiletés

Pour exercer une profession en informatique, il ne suffit pas de connaître un langage de programmation.

Il faut aussi tenir compte de plusieurs éléments :

- **connaissances** : notions techniques, outils, environnement de travail
- **comportements** : rigueur, autonomie, professionnalisme
- **attitudes** : curiosité, ouverture, capacité d'adaptation
- **habiletés** : communication, analyse, résolution de problèmes, travail d'équipe

## Limites d'intervention selon les postes

Tous les postes n'ont pas la même portée.

Par exemple :

- un **programmeur** exécute surtout des tâches de développement précises
- un **analyste** intervient davantage dans l'analyse des besoins et la conception
- un **développeur d'application** peut occuper un rôle plus ou moins large selon l'entreprise

L'important est de comprendre que les titres se ressemblent parfois, mais que les responsabilités peuvent varier.

## Lien avec les conférences et les visites

Les visites servent aussi à mieux comprendre la profession.

Pendant une rencontre avec des membres du milieu, soyez attentifs à :

- leur parcours
- les tâches qu'ils décrivent
- les compétences qu'ils jugent importantes
- la différence entre leur titre et leur travail réel

## Ce qu'il faut éviter

- réduire un poste à une simple liste de technologies
- croire qu'un titre de poste veut toujours dire la même chose partout
- oublier les attitudes et les habiletés

## Activité

Choisissez un **poste précis** lié au développement d'application dans l'**entreprise analysée dans les activités précédentes**.

Basez-vous d'abord sur la **section carrières** de cette entreprise. Si cette section est vide ou ne donne pas assez d'information, cherchez un poste semblable sur un **site d'emploi** comme **Indeed**, dans une entreprise qui oeuvre dans le **même secteur d'activité**.

À partir de ce poste, relevez :

- deux tâches
- deux compétences techniques
- deux habiletés ou attitudes importantes
- une limite d'intervention par rapport à un autre poste proche
